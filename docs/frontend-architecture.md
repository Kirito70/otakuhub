# OtakuHub — Frontend Architecture (Vue 3 + Tailwind CSS + shadcn-vue)

## Overview
Single Vue 3 + TypeScript codebase built with Vite, Tailwind CSS v4, and shadcn-vue primitives.
Targets **Web** (SPA) and **Desktop** (Electron via electron-vite).

> **Note**: This replaces the previous Quasar-based architecture (see ADR 090). All Quasar references have been removed.

## Tech Stack
| Layer | Technology |
|-------|-----------|
| Framework | Vue 3.5+ with `<script setup lang="ts">` |
| Build | Vite 6+ with `@vitejs/plugin-vue` |
| Styling | Tailwind CSS v4 with `@tailwindcss/vite` plugin |
| Primitives | shadcn-vue (Radix-based accessible components) |
| State | Pinia 2.x with `pinia-plugin-persistedstate` |
| Router | vue-router 4.x with named routes and auth guards |
| HTTP | Axios with request/response interceptors |
| Validation | zod for runtime schema validation |
| Desktop | Electron via `electron-vite` |
| Tests | Vitest + jsdom + `@vue/test-utils` |
| Language | TypeScript strict mode — no `any` |

## Key Differences from Quasar Architecture

| Area | Quasar (old) | shadcn-vue + Tailwind (new) |
|------|-------------|---------------------------|
| Build CLI | `quasar dev` / `quasar build` | `vite dev` / `vite build` |
| Layout | QLayout + QDrawer + QFooter | Custom `<AppShell>` with Tailwind grid |
| Dark mode | `$q.dark.set(true)` | Tailwind `dark:` class strategy on `<html>` |
| Forms | QForm + QInput + `lazy-rules` | `<form>` + shadcn `<Input>` + zod validation |
| Cards | QCard + QCardSection | shadcn `<Card>` + `<CardContent>` |
| Buttons | QBtn with `color` prop | shadcn `<Button variant="...">` |
| Dialogs | QDialog | shadcn `<Dialog>` |
| Tabs | QTabs + QTab + QTabPanels | shadcn `<Tabs>` + `<TabsList>` + `<TabsContent>` |
| Select | QSelect | shadcn `<Select>` |
| Badges | QBadge | shadcn `<Badge>` |
| Loading | QSpinner / `$q.loading` | shadcn `<Skeleton>` / custom loading |
| Breakpoints | `$q.screen` JS | Tailwind `sm:`, `md:`, `lg:` in HTML |
| Notifications | `$q.notify()` | Sonner / custom toast |
| Platform targets | Web + Electron + Capacitor (Android/iOS) | Web + Electron only |
| Form validation | Quasar `rules` prop | zod schemas with `useForm` or manual validation |
| CSS architecture | SCSS with BEM overrides | Tailwind utility classes + `@apply` for complex patterns |

## State Management (Pinia)

### Store Structure (always setup syntax)
```typescript
export const useTrackingStore = defineStore('tracking', () => {
  // refs = state
  const entries = ref<ListEntry[]>([])
  const isLoading = ref(false)
  const error = ref<string | null>(null)

  // computed = getters
  const watchingCount = computed(() =>
    entries.value.filter(e => e.status === 'watching').length
  )

  // functions = actions
  async function fetchList() { ... }
  async function updateProgress(mediaId: string, progress: number) { ... }

  return { entries, isLoading, error, watchingCount, fetchList, updateProgress }
})
```

### Auth Store (persisted)
The auth store uses `pinia-plugin-persistedstate` to survive page refresh.
On web: persists to localStorage.
On Electron: persists to localStorage or electron-store.

## HTTP Client (Axios)

### `src/plugins/axios.ts`
```typescript
import axios from 'axios'
import { useAuthStore } from '@/stores/auth'

const api = axios.create({ baseURL: import.meta.env.VITE_API_BASE_URL })

// Request interceptor: attach token
api.interceptors.request.use(config => {
  const auth = useAuthStore()
  if (auth.accessToken) {
    config.headers.Authorization = `Bearer ${auth.accessToken}`
  }
  return config
})

// Response interceptor: refresh on 401
api.interceptors.response.use(
  res => res,
  async err => {
    if (err.response?.status === 401 && !err.config._retry) {
      err.config._retry = true
      const auth = useAuthStore()
      await auth.refreshToken()
      err.config.headers.Authorization = `Bearer ${auth.accessToken}`
      return api(err.config)
    }
    return Promise.reject(err)
  }
)

export { api }
```

## Routing

### Auth Guard
```typescript
// src/router/index.ts
router.beforeEach((to) => {
  const auth = useAuthStore()
  if (to.meta.requiresAuth && !auth.accessToken) {
    return { name: 'login' }
  }
  if (to.name === 'login' && auth.accessToken) {
    return { name: 'discover' }
  }
})
```

## Page State Pattern
Every page must handle four states:
1. **Loading**: `<Skeleton>` components matching layout
2. **Empty**: `<AppEmptyState mode="empty" title="..." />`
3. **Error**: `<AppEmptyState mode="error" title="..." :onAction="retryFn" />`
4. **Content**: Actual data

## Form Validation Pattern
```typescript
import { ref } from 'vue'
import { z } from 'zod'

const loginSchema = z.object({
  username: z.string().min(1, 'Username is required'),
  password: z.string().min(1, 'Password is required'),
})

type LoginForm = z.infer<typeof loginSchema>

const form = ref<LoginForm>({ username: '', password: '' })
const errors = ref<Partial<Record<keyof LoginForm, string>>>({})

function validate(): boolean {
  const result = loginSchema.safeParse(form.value)
  if (!result.success) {
    errors.value = Object.fromEntries(
      result.error.errors.map(e => [e.path[0], e.message])
    )
    return false
  }
  errors.value = {}
  return true
}
```
